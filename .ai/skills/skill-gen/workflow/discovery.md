# 阶段 1：Skill Discovery

目标：确认"要改善的工作"，而不是先确认"要建一个 Skill"。

## 说明

- 本阶段可以创建或更新 DESIGN.md，它是设计工作记录。
- 本阶段不创建或修改实现文件（SKILL.md、rules/、workflow/、reference/、scripts/、templates/）。

## 执行顺序

1. **复述理解**
   - 用一句话说明你认为用户想改善的工作、使用者和场景。
   - 不确定就直说，不要编造。

2. **检查现有覆盖**
   - 列出技能目录（默认 `~/.claude/skills/`，以实际加载路径为准）；存在项目级技能目录（如项目内 `.claude/skills/` 或 `.ai/project/skills/`）时一并检查。
   - 读取各 SKILL.md 的 description 和路由，判断是否已有技能覆盖。
   - 只看目标和触发范围，不急着看实现细节。

3. **判断是否值得建，以及采用哪种方式**
   - 一次性操作、普通问答：不建，直接完成。
   - 内容全是通用知识、没有项目或个人约束：不建。
   - 已有技能覆盖：判断扩展或重构。
   - 新领域或触发范围不重叠：新建。

4. **梳理未知**
   - 列出还不清楚的信息，按"是否影响设计方向"排序。
   - 只问最关键的 1-3 个；其余列入 Part 1 Open Questions。

5. **写 DESIGN.md Part 1**
   - 新建技能：创建目录和 DESIGN.md（参考 `../templates/DESIGN.md.tmpl`），状态 Draft。
   - 扩展/重构且已有 DESIGN.md：更新现有记录。
   - 扩展/重构但没有 DESIGN.md：新建 DESIGN.md，从现有实现反推基线，全部标 `[推断]`，请用户确认后再继续。
   - 用户确认的标 `[已确认]`，AI 提议标 `[建议]`，未定标 `[待确认]`。

## 新建 / 扩展 / 重构 / 不建

| 判断 | 条件                                             | 动作               |
| ---- | ------------------------------------------------ | ------------------ |
| 新建 | 新领域，或触发范围与现有技能不重叠               | 建新技能目录       |
| 扩展 | 同领域、同类型、共享触发方式和规则               | 修改现有技能       |
| 重构 | 现有技能职责或流程需要重新划分                   | 先改设计，再改实现 |
| 不建 | 一次性操作、通用知识、普通提示词即可完成         | 说明原因并直接处理 |

- 同领域不同类型（工具型 vs 业务型）通常新建。
- 同领域同类型的新子命令通常扩展。
- 多个现有技能都沾边时，列为 Open Question 让用户定边界，不要自行合并。

## 提问方式

- 一次最多 3 个问题，优先问会改变设计方向的问题。
- 能给出选项时优先用选项卡（如 AskUserQuestion），给出推荐项和理由。
- 不要要求用户一次提供完整需求；用户说"不知道"时，给 2-3 个候选方案让其选择。
- 可以先说明假设、请用户确认或修正，而不是空等回答。

## 本阶段禁止

- 不创建或修改实现文件：SKILL.md、rules/、workflow/、reference/、scripts/、templates/。
- 不因为用户说"创建一个 skill"就直接进入生成。
- 不为了流程完整而追问用户明显不关心的细节。

## 收尾

向用户输出：

1. 理解的问题和场景（简短）。
2. 建议：新建 / 扩展 / 重构 / 不建，及理由。
3. Part 1 草案位置和 `[待确认]` 清单。

用户认可判断后进入阶段 2。
