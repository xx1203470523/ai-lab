# Skill Gen

## 判断流程

收到创建/优化请求后，按以下顺序判断：

### 1. 是否适合建技能

以下场景**不适合**建技能，直接告知用户原因：

- 操作过于简单（单条命令、一次文件读写），模型通用知识已覆盖
- 内容全是 AI 已知的通用知识（如"git rebase 教程"），没有项目特定约束
- 已有 skill 覆盖该场景，只需扩展

### 2. 是否整合到现有技能

检查已有 skill 的覆盖范围，判断是扩展还是新建：

- 同领域同类型 → 扩展（如新的 git 子命令加进 git skill）
- 同领域不同类型 → 新建（如 git 是工具型，WMS 发布是业务型）

### 3. 确定技能类型

| 类型       | 特征                                     | 命名            | 示例                                        |
| ---------- | ---------------------------------------- | --------------- | ------------------------------------------- |
| **工具型** | 无业务逻辑、确定性操作、跨项目复用       | `<name>`        | `git`、`task-plan`、`task-execute`          |
| **业务型** | 领域特定、含业务规则、可能协调多个子技能 | `<业务>-<模块>` | `wms-backend-dev`、`wms-pda`、`trade-watch` |

## 创建

### 核心原则

1. **只写 AI 不知道的**：项目特定约束、个人偏好、环境信息。通用操作步骤不写
2. **渐进式披露**：SKILL.md 内联核心规则 + 路由表，详细内容放 workflow/rules/reference
3. **文件不过度碎片化**：3-4 行的规则不值得独立文件，合并到上级
4. **空目录放 `.gitkeep`**：保证 git 追踪完整目录结构

### 规则写作约束

禁止在规则文件中使用以下写法，这些属于 AI 已知的解释性废话：

- 解释原因：`系统工具可能...`、`因为...`、`由于...`
- 解释范围：`包括但不限于...`、`等常见情况`
- 操作指引：`提交前必须确认...`、`若发现...则立即用...`
- 强调修饰：`**强制**禁止`（`禁止` 已足够）、`必须严格遵守`
- 每条规则只写"禁止什么"或"必须什么"，一行写完，不拆多行不写 why

### 目录结构

**工具型**：

```
<name>/
├── SKILL.md          # 核心规则 + 路由表 + 未匹配兜底
├── rules/            # 项目特定约束（按需）
├── workflow/         # 多步骤流程（按需）
└── reference/        # 模板、覆盖配置（按需）
```

**业务型**：

```
<business>-<module>/
├── SKILL.md          # 协调入口：路由 + 子技能分发 + 安全规则
├── rules/            # 业务规则（conditional rule packs）
├── workflow/         # 多步骤协作流程
├── reference/        # 领域知识、模板
└── scripts/          # 自动化脚本
```

### SKILL.md 模板

**工具型** — 参考 `ai-lab://.ai/skills/skill-gen/templates/tool/`

```markdown
---
name: <name>
description: "<功能描述>。触发关键词：<中文>、<英文>、/<name>"
---

# <Title>

## 核心安全规则

<始终有效的约束，3-6 条>

## 路由

| 命令 | 入口                                    | 说明     |
| ---- | --------------------------------------- | -------- |
| ...  | `./workflow/xxx.md` 或 `./rules/xxx.md` | 简短说明 |

## 未匹配命令

若用户意图不在以上路由中，直接用通用知识处理。不要加载 workflow/ 和 rules/。
```

**业务型** — 参考 `ai-lab://.ai/skills/skill-gen/templates/business/`

```markdown
---
name: <business>-<module>
description: "<业务描述>。触发关键词：<中文>、<英文>、/<business>-<module>"
---

# <Title>

## 协调规则

<跨子技能的协调约束>

## 子技能路由

| 子技能 | 触发场景 | 详细入口            |
| ------ | -------- | ------------------- |
| ...    | ...      | `./workflow/xxx.md` |

## 安全规则

<始终有效的业务约束>
```

### description 写法规约

- 中英混合关键词，覆盖常见叫法
- 明确"仅在...时触发"的边界，避免误触发
- 不用 `,` 分隔关键词，用 `、`

## 优化

优化已有 skill 时：

1. 检查文件碎片化（3-4 行的独立文件合并）
2. 检查是否写了 AI 已知内容（删除冗余说明）
3. 检查 description 是否太宽（收窄触发范围）
4. 检查是否有未匹配兜底逻辑
