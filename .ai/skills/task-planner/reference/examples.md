# Task Planner Examples

## L1：不生成 Spec

输入：“把这个错误提示里的‘失败’改成‘处理失败’。”

判断：局部文本修改，无业务行为、契约、状态或跨模块影响。

输出：说明目标文件和一个验收点，交给普通实施流程；不创建 DRAFT 文件。

## L2：轻量 Spec

输入：“列表接口增加按单号筛选，保持原有分页和返回结构。”

应确认：入口、参数 DTO、查询实现、现有分页契约和调用方。若代码已明确且不跨端行为，生成短 Spec：

- Facts：现有路由/DTO/查询方法，均带 `path:line`。
- Inference：新增可选参数不会改变旧调用结果。
- Decision：若旧客户端无法忽略未知字段，则列为用户确认；否则不制造问题。
- Acceptance：有筛选/无筛选/空值/分页边界，旧响应结构不变。

## L3：完整 Spec

输入：“入库收货完成后改成新的库存模型，同时保持 PDA 操作流程不变。”

必须检索：PDA 扫描与提交步骤、API DTO/Controller、收货 Service、库存实体/Repository、事务边界、库存查询消费者、权限和类似库存模型。

关键输出：

- Facts：当前收货完成触发点、写入表/实体、PDA 调用链、状态转移和事务证据。
- Inferences：新模型可能需要保留旧查询适配层；这只是技术推断。
- Decisions：库存余额语义、历史数据是否迁移、旧接口是否兼容、重复提交如何处理、PDA “流程不变”具体验收动作。
- Out of Scope：未被需求影响的出库、盘点、打印或其他端行为，除非证据显示它们消费同一契约。
- Acceptance：成功收货、重复提交、部分失败、并发、旧客户端、PDA 步骤和最终库存状态。

若任一 Decision 未确认，保持 `DRAFT`，不要交给 Implementer。

## L4：高风险 Spec

输入：“把旧库存表迁移到新模型并清理历史脏数据。”

除 L3 内容外必须明确：迁移窗口、备份、回滚、幂等重跑、对账口径、脏数据处理规则、锁/并发、权限、旧读写切换、失败补偿和逐条验证。任何删除或数据语义选择都必须由用户确认；不能因为迁移脚本可写就直接执行。
