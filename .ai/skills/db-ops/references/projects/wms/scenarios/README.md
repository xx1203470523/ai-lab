# WMS 专属剧本

本目录放**只对 WMS 成立**的排查剧本。与项目无关的通用剧本放技能根目录的 `scenarios/`。

## 证据要求

每条结论必须能追到下面两种来源之一，并**写出具体位置**：

1. **代码证据**：实体文件/服务文件的路径 + 行号（例如 `InStockArnHead.cs:59` 的 `Dept` 属性）。
2. **实测证据**：一次真实查询的结果（写清路由、库名、时间）。

两者都没有的，只能写进「残留不确定性」，**不得**写成结论。

## 三个容易自欺的来源

- **注释掉的旧代码**。`InstockArnHeadRepository` 里那句注释态的 `left join sys_dept de on T1.Dept = de.Id` 就是典型：它看起来是权威写法，实际早就不可用（见 `arn-head-dept-shows-none.md`）。注释不是证据。
- **工具侧配置**。`tools/库存比对/inventory_diff_config.ini` 是工具配置，不是应用真值（见 `references/projects/wms/routes.md`）。
- **界面现象**。界面上显示「无」既可能是数据没有值，也可能是取数逻辑错了。剧本要能区分这两者，不能把现象当结论。

## 状态标注

每个剧本头部必须写：

```
状态：已验证 | 未验证
最后验证时间：YYYY-MM-DD
适用路由：<路由 id>
```

- **未验证**的剧本在使用时必须降级为一次普通排查，不得作为结论依据。
- **适用路由**要写清：WMS 每个据点独立部署，同一张表在不同据点上可能装着完全不同的数据。**在错的库上排查，得到的证据比没有证据更糟。**

## 与 `sql/` 的分工

- 剧本回答「怎么判断、怎么处置」。
- `sql/` 存「值得复用的语句本身」，按 `sql/README.md` 的规范归档。
- 剧本里的诊断语句如果通用性强，归档一份到 `sql/`，并在剧本里保留原句（剧本要能独立读懂）。
