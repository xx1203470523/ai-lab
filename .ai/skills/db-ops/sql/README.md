# `sql/` 归档规范

本目录存**个人可复用的只读查询**。它不是项目发布 SQL 的仓库——见下面的边界。

## 边界：不要和生产变更 SQL 混在一起

| 内容 | 归属 |
|---|---|
| 生产/发布用的变更 SQL、回滚、历史归档 | **项目仓库**：`<repo>/sql/`（`publish/yyyy-MM-dd/`、`history/v{version}/`、`tool/`、`logs/yyyy-MM-dd/`），按该仓库自己的 `sql/index.md` 规范走 |
| 个人反复要用的排查查询、口径核对语句 | **本目录 `queries/`** |
| 可复用的写操作**模板**（泛化、不含真实 Id、技能不执行） | **本目录 `operations/`**，见下节 |

理由：项目发布 SQL 有发布流程与审核，必须进版本库；个人查询是工作台产物，混进仓库会污染索引，混进技能目录的发布 SQL 则会绕过审核。**三边都不要放错。**

## `operations/` 与项目仓库发布 SQL 的区别

`operations/` 放的是**模板**，不是某一次变更的脚本：

| | `operations/` 模板 | 项目仓库 `publish/` 脚本 |
|---|---|---|
| 内容 | 泛化的操作骨架，守卫与顺序固化 | 针对具体环境、具体 Id 的一次性变更 |
| 标识 | 只有占位符（`<菜单Id>`、`@id_base` 示例值） | 真实菜单 Id、真实备份表名、真实日期目录 |
| 执行 | **技能不执行，任何脚本也不执行**；执行由人把模板实例化后放进项目仓库再跑 | 人工在数据库客户端执行 |
| 目的 | 让下一次同类操作不必重新推守卫和顺序 | 留档这次改了什么、怎么回滚 |

**判据**：文件里出现真实菜单 Id / 具体据点的库名 → 它属于项目仓库；只有占位符与守卫逻辑 → 它属于 `operations/`。

`operations/` 里的文件**不登记进 `index.md`**（那个索引是只读查询的索引）；它们的说明写在 `logs/` 下同批次的变更说明里。

## 什么值得归档

三条同时满足才归档：

1. **会重复用**——一次性的问题查完就丢，不进 `sql/`。
2. **只读**——`SELECT` / `SHOW` / `DESCRIBE` / `EXPLAIN` / `WITH`。写语句按 `workflows/exec-flow.md` 处理：
   **具名的一次性变更进项目仓库**；抽掉真实 Id、只剩守卫与顺序的**通用模板进 `operations/`**；两者都**不进 `queries/`**。
3. **不绑定临时条件**——把单号、日期这类每次都变的值写成占位符（`<单号>`、`<起始时间>`），不要把某一次的具体值写死。

## 目录结构

```
sql/
├─ README.md              # 本文件：规范
├─ index.md               # 索引：一行一条，指向 queries/ 归档文件与其说明
├─ queries/               # 归档的只读查询（首次归档时创建）
│  └─ q_<用途>.sql
├─ operations/            # 写操作模板（泛化、不含真实 Id，技能不执行，不登记 index.md）
│  └─ menu_cleanup.sql / menu_update.sql
└─ logs/yyyy-MM-dd/       # 归档与变更说明（首次归档时创建）
   └─ <用途>.md
```

- 文件名：`q_<用途>.sql`，用途用英文小写下划线（`q_arn_dept_source.sql`）。
- **同一个用途改了口径就改原文件并记一条日志**，不要新建 `q_xxx_v2.sql`——版本差异靠日志表达，靠文件名表达会让人不知道该用哪个。

## 每个归档文件的必备元信息

SQL 文件头部用注释写清（缺一项都不算归档完成）：

```sql
-- 用途：<一句话，说明它回答什么问题>
-- 路由：<路由 id>（库名：<db>）
-- 实体依据：<实体文件:行号，例如 Domain.Warehouse/Entities/InStock/InStockArnHead.cs:59>
-- 软删除：<是否加了 IsDeleted = 0，依据是该实体是否实现 IDeletedFilter>
-- 收窄条件：<必须替换的占位符>
-- 验证时间：YYYY-MM-DD
```

- **不写库名/schema 前缀**：库由路由决定（见 `rules/db-ops.rules.md` R1）。
- **不写凭据、不写连接串**：本目录会进版本库，注释里的口令同样算泄漏。
- **软删除依据必须写**：`IsDeleted` 列几乎每张表都有，但应用只对实现了 `IDeletedFilter` 的实体过滤（`references/projects/wms/orm-boundaries.md`）。写错方向会静默少查或多查数据。

## 日志要写什么

`logs/yyyy-MM-dd/<用途>.md` 至少包含：为什么加这条查询、验证方式（在哪条路由上跑过、结果是否符合预期）、以及**已知的局限**（哪些情况它判断不出来）。

写「没验证」比写「看起来对」有价值——下一个人据此决定要不要再查一遍。

## 索引怎么维护

`index.md` 一行一条：日期、文件、用途、路由、验证时间。**新增或修改归档时同步更新索引**，索引与文件不一致时以文件为准并立刻修索引。
