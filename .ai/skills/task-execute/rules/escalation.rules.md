# 扩散检索与升级规则

## 定义

**扩散检索**：Agent 在 plan manifest 指定的文件列表之外，额外读取任何文件，每次读取计 1 次。

以下不计入扩散检索次数：
- 读取前序包的输出文件（自动加入上下文）
- 读取 manifest 中已列出的文件
- 同一文件多次读取只计 1 次

## 次数限制

| 次数 | 行为 |
|------|------|
| 1-3 次 | 自动允许，Agent 可继续执行 |
| 第 4 次 | 停止执行，回报主会话 |

Agent 内部自行追踪扩散检索次数，第 4 次时必须立即停止。

## 升级回报格式

Agent 停止时必须输出以下格式：

```
[ESCALATE] 扩散检索已达 3 次上限
已检索文件：
  - <文件路径>：<检索原因>
  - <文件路径>：<检索原因>
缺失信息：<具体描述缺少什么信息>
建议：<是否需要继续扩散、需要读取哪些文件>
状态：等待主会话确认
```

## 主会话判断

收到 `[ESCALATE]` 后：

1. **批准继续** → Agent 重新获得 3 次配额，继续执行
2. **拒绝继续** → 标记当前包为 `blocked`，记录阻塞原因：`扩散检索超限：{缺失信息}`
3. **修改 manifest** → 用户补充 manifest 文件列表后，重置配额，重新启动该包

## 禁止扩散到禁止路径

扩散检索同样受 `boundaries.forbid` 约束：
- 禁止路径内的文件不计入扩散检索——直接拒绝读取
- Agent 尝试读取禁止路径 → 立即停止，回报：`[ESCALATE] 尝试读取禁止路径：{路径}`

## 范围扩大升级

Agent 发现任务范围超出 contract.out_of_scope 时，不计入扩散检索次数，直接停止并回报：

```
[ESCALATE] 任务范围扩大
原始范围：{contract.in_scope}
发现扩大：{具体描述}
建议：{是否应修正计划、新增包或调整 contract}
状态：等待主会话确认
```
