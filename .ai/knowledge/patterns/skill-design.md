# Skill 设计方法论

> 最后更新: 2026-07-02

## 核心原则

### 渐进式披露
- SKILL.md 内联核心规则（始终在上下文中）
- 详细流程放 workflow/，用到才加载
- 规则约束放 rules/，workflow 步骤中按需引用
- 通用知识不写——AI 已经知道

### 触发词设计
- description 是中英混合关键词，覆盖常见叫法
- 收窄触发范围避免误触发（不需要的 skill 加载浪费 token）
- 未匹配命令加兜底逻辑，防止无效文件读取

## 目录结构

```
skill-name/
├── SKILL.md          ← 入口：核心规则 + 路由表 + 兜底
├── rules/            ← 约束规范（AI 不知道的项目特定规则）
├── workflow/         ← 多步骤执行流程
├── reference/        ← 模板、示例、项目特定覆盖
└── knowledge/        ← 可选：领域知识
```

## 反模式

- 文件碎片化：3-4 行的规则不值得独立文件（延迟 > 收益）
- 教程式 workflow：AI 已知的通用步骤不写
- 双轨并行：同一功能不要有多个 skill 覆盖
