# Knowledge Manage — WMS 知识库管理

## Trigger

- 用户说"沉淀到知识库"、"这个写进 knowledge"
- 排查完一个领域逻辑后需要记录
- 新增/更新/检索知识库条目
- 更新 `knowledge/INDEX.md` 索引

## 知识库结构

```
knowledge/
├── INDEX.md          # 索引（唯一入口，按关键词检索）
├── backend/          # 后端：实体、服务、数据库、领域规则
├── frontend/         # 前端：页面、组件、路由
├── pda/              # PDA：扫码、设备、离线
└── scripts/          # 检索脚本 search-knowledge.ps1
```

## 知识文件格式约定

每个知识文件必须包含：

```markdown
# 标题（简洁描述）

> 最后更新: YYYY-MM-DD
> 来源：一句话说明原始场景

## 一、...(核心内容分区)
## 二、...

## N、关键代码位置

| 文件 | 行号 | 内容 |
|------|------|------|
```

**格式规则**：
- 用表格承载字段映射、枚举、决策分支
- 用代码块只写关键行（引用文件路径即可，不贴完整代码）
- 必须包含"关键代码位置"表，用于日后验证知识是否过期
- 禁止写推测性内容；只写已从代码确认的事实

## 操作流程

### 1. 沉淀新知识（Create）

1. 判断归属目录（`backend/` / `frontend/` / `pda/`）
2. 命名：`<主题-kebab-case>.md`（如 `qual-judgment.md`、`upshelves-label.md`）
3. 按格式约定写入
4. 更新 `INDEX.md`：添加关键词行、更新"待建"状态

### 2. 检索知识（Search）

直接 `Grep` 关键词到 `knowledge/` 目录，或读取 `INDEX.md` 查索引。

### 3. 更新已有知识（Update）

1. 读取目标文件
2. 更新内容 + 更新"最后更新"日期
3. 如新增关键词，同步更新 `INDEX.md`

## 分类规则

| 内容类型 | 目录 | 示例 |
|---------|------|------|
| 实体/服务/数据库/领域规则/枚举映射 | `backend/` | 质检判定字段、上架标签来源 |
| 页面/组件/路由/交互规则 | `frontend/` | 报表 schema 设计、打印模板 |
| 扫码/设备/离线/设备API | `pda/` | 扫描流程、设备常量 |

## 禁止事项

- 禁止写推测性内容（"可能"、"应该"），只写代码确认的事实
- 禁止贴完整代码块（超过 20 行），改为文件路径+行号引用
- 禁止不加"最后更新"日期
- 禁止不更新 INDEX.md 就新增文件
- 禁止跨域混合（一个文件只归属一个目录）
