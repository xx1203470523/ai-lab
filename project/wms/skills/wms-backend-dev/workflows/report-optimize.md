# Report Optimize Workflow

用于 WMS 报表新增、优化、重构任务的执行流程。

本 Workflow 只负责任务阶段、决策节点和状态流转。

具体约束遵循：

- Service Rules
- DTO Rules
- Repository Rules
- Report Rule Pack

实现方案参考：

- Report Knowledge
- Report Template

## 1. Trigger

以下场景进入本 Workflow：

- 新增报表
- 优化报表查询性能
- 优化分页或导出
- 调整报表 DTO 结构
- 分析报表慢查询
- 处理大数据量导出问题

## 2. Assessment

执行前完成当前报表评估：

确认：

- 当前入口
- 影响层级
- 查询范围
- DTO结构
- 分页方式
- 导出方式
- 数据量风险
- API契约影响

输出：

- 当前问题
- 风险点
- 改造范围
- 是否需要拆分任务

## 3. Solution Design

根据影响范围选择方案：

### 保守优化

适用于：

- 查询条件保护
- 参数校验
- 局部查询优化
- 增加限制

### 结构优化

适用于：

- 分离分页和导出
- 调整查询构建方式
- DTO职责调整

### 重构方案

适用于：

- API变化
- 字段语义变化
- V2切换
- 多端影响

高风险方案必须先确认。

## 4. Task Contract

进入修改前明确：

- 修改目标
- 修改范围
- 不修改范围
- 影响层级
- 影响消费者
- 验证方式
- 停止条件

无法明确范围时进入 Blocked。

## 5. Implementation

按照确定方案执行：

- 小范围修改优先
- 保持已有业务语义
- 避免扩大修改范围
- 分阶段提交验证

## 6. Verification

完成后确认：

- 功能是否符合目标
- 查询结果是否变化
- DTO/API是否兼容
- 是否存在性能风险
- 是否存在未验证项

输出：

- 已完成
- 已验证
- 未验证
- 风险
- 后续建议
