# WMS Dev Base Rules

本文件定义 WMS 开发所有任务必须遵守的基础约束。

具体领域规范由对应 Domain Rules 和 Conditional Rule Packs 提供。

---

## 1. Change Scope

所有代码修改必须遵循最小变更原则。

必须：

- 明确修改目标、入口和影响范围。
- 优先局部优化，不主动扩大重构范围。
- 保持已有业务行为和接口契约。

禁止：

- 未确认的大范围重构。
- 未确认的业务逻辑调整。
- 为"未来可能使用"提前设计无关代码。

---

## 2. Contract Safety

以下内容属于契约变化：

- API 入参/出参。
- DTO字段新增、删除、修改。
- Web/PDA调用结构。
- 打印、导出格式。
- 外部系统接口。

契约变化必须：

- 明确影响范围。
- 确认消费者。
- 单独评估。

---

## 3. Business Safety

涉及以下业务对象时，不允许仅根据代码猜测业务：

- 库存数量。
- 库存状态。
- 标签生命周期。
- 单据状态流转。
- 质检状态。
- T100/ERP交互。
- 立库流程。

发现业务含义不明确时：

- 停止扩大实现。
- 提出风险。
- 等待确认。

---

## 4. Dependency Safety

修改公共代码、公共方法、公共服务时：

必须评估：

- 当前调用方。
- 是否存在多个业务入口。
- 是否影响其他模块。

禁止：

- 删除未知用途方法。
- 修改公共方法语义但不通知影响范围。

---

## 5. Data Safety

涉及数据库操作时：

必须：

- 明确数据范围。
- 避免无条件大范围查询。
- 避免可能影响生产的数据操作。

禁止：

- 无条件全表查询。
- 未确认的数据修复脚本。
- 未评估的大批量更新删除。

---

## 6. Verification

完成修改后必须输出：

- 修改内容。
- 修改文件。
- 验证方式。
- 未验证项。
- 潜在风险。

未经明确授权：

- 不主动执行 build/test。
- 不执行生产数据操作。

---

## 7. Unknown Handling

当出现以下情况：

- 调用链不明确。
- 数据来源不明确。
- 字段含义不明确。
- 历史逻辑目的不明确。

禁止自行假设。

应：

- 标记未知点。
- 给出影响范围。
- 请求确认。
