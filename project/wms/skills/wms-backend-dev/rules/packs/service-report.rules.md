# Service Report Rule Pack

命中条件：任务涉及 WMS 报表新增、报表优化、报表分页查询、报表列表查询、报表导出、MiniExcel、大数据量查询、查询防刷、报表字段语义或报表 DTO 分离。

## 1. Report Scope

- 报表任务仍归属 `wms-service`，同时命中 Repository 查询、DTO 或 Controller 契约时必须读取对应规则包。
- 报表新增或优化默认只处理一个明确报表、入口、方法或业务闭环，禁止一次性批量改造多个无关报表。
- 报表优化必须保护原字段含义、原筛选语义、原排序语义和原导出业务含义。
- 发现字段含义不明确、历史注释与代码不一致、DTO 字段可能影响 Web/PDA/API/导出消费者时，必须进入确认，不得自行改字段语义。
- 优化建议可以列出字段冗余、字段来源不合理、索引缺失或冗余字段候选，但未经确认不得落地为契约变更。

## 2. Query Gate

- 新增报表必须定义最小有效查询条件；优化旧报表时必须评估是否允许无条件查询。
- 数据量大的报表默认不允许首次进入即查询全量；查询条件不足时应使用项目既有业务异常提示用户补充条件。
- 大表报表至少需要单号、标签、批号、物料编码、主业务状态、时间范围或其他高选择性条件之一。
- 只有名称、备注、供应商名称、人员名称等弱条件时，应结合时间范围、业务状态或最大跨度限制。
- 禁止为了兼容旧行为静默放开大范围查询；需要保留旧行为时必须向用户说明性能风险并确认。

## 3. String Match

- 报表查询禁止全模糊匹配，例如 `Contains`、`%keyword%` 或等价写法。
- 字符串弱匹配默认使用右模糊语义，例如 `StartsWith` 或数据库可利用前缀索引的等价写法。
- 单号、标签号、批号、SN、Id、枚举、状态、日期范围等高选择性字段优先使用等值、范围或集合匹配。
- 多单号输入可支持明确分隔符拆分后的集合匹配，但必须过滤空值并评估集合大小。
- 不允许把全模糊隐藏在私有方法、Repository helper、原生 SQL 或动态条件中。

## 4. Id Prequery Strategy

- “先查 Id 再带入主查询”只能作为可选小结果集策略，不能作为报表默认优化手段。
- 适合 Id 预查的场景包括用户、字典、仓库、项目、物料等维表条件转换，且预期命中数量较小。
- 不适合 Id 预查的场景包括库存、标签、出入库明细、质检明细、调拨明细等大明细表反查单头。
- 大结果集、数百个以上 Id 或无法确认数量时，应优先评估 Join、Exists/Subquery 或主查询条件下推。
- 使用 `Take(n)`、分页预查或上限保护时，必须定义超过上限时的业务处理；禁止静默截断导致报表结果不完整。
- `Contains(ids)` 只用于小集合；大集合必须评估 SQL 长度、执行计划、临时表或改用 Join/Subquery 的必要性。

## 5. Paging Query

- 高风险报表不应直接把完整查询交给 `ToPageAsync` 后才处理风险。
- 分页推荐拆出：查询条件校验、基础查询构建、数量评估、分页数据查询、当前页补充字段填充。
- 如果 `ToPageAsync` 同时 count 和分页导致无法设置保护点，应改为显式 count 与分页查询，或先输出风险方案等待确认。
- Count 结果超过报表允许阈值时，应提示用户增加查询条件，而不是继续拉取分页或导出。
- 分页后的补充字段只能基于当前页相关 Id 集合查询；禁止为了补充字段查询全量相关数据。
- 排序必须明确且稳定；没有业务排序时应说明默认排序依据，避免分页结果漂移。

## 6. Export Query

- 报表导出统一使用 MiniExcel 或项目既有 MiniExcel 封装，不新增其他 Excel 库。
- 导出 DTO 必须与页面展示 DTO 分离，使用 `XxxExportDto` 表达导出列和导出字段顺序。
- 导出前必须有 count、limit probe 或等价数量评估；禁止先 `ToListAsync()` 全量加载后再判断是否超限。
- 超过导出上限时必须阻断并提示用户增加查询条件。
- 大批量导出不得无控制地一次性加载全部实体和全部转换结果；需要分批、流式或分段方案时必须说明内存风险和实现边界。
- 导出方法不得直接复用分页方法来假装全量导出；应复用基础查询和字段填充逻辑，但分页、列表和导出入口语义要分清。
- 导出必须考虑用户维度或报表维度的并发限制；加锁时必须在 `finally` 中释放，未取得锁不得释放。

## 7. DTO Shape

- 新增报表默认拆分 `XxxQueryDto`、`XxxPagedQueryDto : PagerQuery`、`XxxDto` 和 `XxxExportDto`。
- `XxxQueryDto` 只承载业务查询条件，不继承分页基类。
- `XxxPagedQueryDto` 承载分页参数和业务查询条件；可通过 Mapster 或显式映射转为 `XxxQueryDto`。
- 优化旧报表时，DTO 拆分若影响 API 请求体、响应体、Web 表格、PDA 或导出列，必须先确认。
- DTO 字段删除、重命名、类型变化、可空性变化、枚举语义变化和导出列变化均属于契约风险。

## 8. Performance Analysis

- 性能分析可使用 `/dbsql` 或用户授权的只读数据库查询。
- 允许查询表结构、索引、估算行数、条件 count、执行计划或小样本 limit 分页。
- 禁止执行全量查询、无条件导出、无条件大范围 select 或会阻塞业务的压力测试。
- 数据库验证必须明确 SQL 条件、limit、预估数据量和是否命中索引。
- 没有数据库访问授权时，应基于代码结构、表关系和查询形态给出风险判断，不得编造数据量结论。

## 9. Refresh And Concurrency Limit

- 报表导出必须评估重复点击、重复导出和同用户并发导出的风险。
- 高成本分页查询应评估查询防刷、短 TTL 锁、前端防抖、后端冷却时间或异步任务化方案。
- 防刷规则不得影响不同用户的正常业务查询，除非用户明确要求全局限流。
- 限制策略必须返回业务可理解的提示，例如“查询过于频繁，请稍后重试”或“正在导出，请稍后重试”。

## 10. Verification

- 报表优化验证必须至少覆盖查询条件不足、正常分页、无结果、超上限导出、字段含义保持和并发限制中的命中项。
- 未经用户明确授权不主动运行 build/test；未运行时必须说明未验证项。
- 完成前必须检查本次改动范围内无无用 using、无用注入字段、无用私有方法、临时变量、调试输出和注释废代码。
